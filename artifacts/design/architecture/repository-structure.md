# W6W repository structure and ownership

This document maps the parent folder structure supplied with the project to the implemented W6W code. Production Java belongs to Maven modules under `code/platform/modules`; workflow definitions belong to `code/workflows`. `Readme.md` remains the combined SRS and implementation plan.

## Ownership and change flow

1. A workflow author changes only the workflow package and shared assets; CI validates CWM, lints, compiles, and runs its scenarios.
2. A platform change runs all platform tests and cross-checks every workflow against that platform revision.
3. CWM YAML and forms are authoritative. BPMN/DMN are generated artifacts and stay out of Git.
4. Migration outputs are draft pull-request content. They cannot be deployed until unknown constructs are resolved, the CWM linter passes, and a human reviews the report.
5. `data/`, Maven `target/`, `code/workflows/build/`, and ordinary test reports are generated outputs, not source files.

## Repository evolution

The current repository keeps the user-supplied top-level `artifacts/`, `code/`, `prompts/`, `Readme.md`, and `RULES.md`. The bundled web workspace and CLI are a local integration slice; production identity and authorization, production deployment, durable operations runbooks, and full acceptance coverage remain open. See [the SRS traceability matrix](../srs/traceability.csv) for implementation state by requirement.
